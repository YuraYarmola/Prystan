# Що є в конкурентів, чого ще немає в Prystan

> Дата: 2026-08-06 · Порівняно з: Docker Desktop, Portainer BE/CE, JetBrains Docker plugin, lazydocker, OrbStack, Dokploy/Komodo
> Поточний стан Prystan: 63 команди бекенда, ~5 500 рядків, усі фічі рівнів A/B/C з ROADMAP реалізовано.

---

## 1. Головні прогалини (те, за чим реально повертаються в інші інструменти)

### 1.1 Сканування образів на вразливості
**У кого:** Docker Desktop (Docker Scout), Portainer BE (Trivy).
Scout розбирає образ пошарово, зіставляє пакети з 23 базами вразливостей, показує, у якому саме шарі проблема, і пропонує виправлення. Працює постійно — коли зʼявляється новий CVE, він позначає вже просканований образ.

**Чому важливо для нас:** на ваших серверах 96 образів. Зараз немає жодного способу дізнатись, у якому з них дірявий OpenSSL.
**Як зробити дешево:** запускати `aquasec/trivy` як разовий контейнер на тому ж демоні (`docker run --rm -v /var/run/docker.sock trivy image <img>`) і показувати результат таблицею. Без хмари й ліцензій. **Складність: середня.**

### 1.2 Перегляд шарів образу (image layers)
**У кого:** JetBrains plugin, Docker Desktop.
Показує, який шар скільки важить і якою командою Dockerfile створений — головний інструмент, коли образ роздувся до 2 ГБ.

**У нас:** є лише сумарний розмір образу.
**Як зробити:** `GET /images/{name}/history` — Docker уже віддає готовий список. **Складність: низька.** Найкраще співвідношення користі до зусиль із усього списку.

### 1.3 Diff файлової системи контейнера
**У кого:** JetBrains plugin, Docker Desktop.
Показує, що змінилося всередині контейнера з моменту запуску (A/C/D — додано, змінено, видалено).

**Навіщо:** зрозуміти, що процес насмітив у контейнер, або чому контейнер розпух.
**Як зробити:** `GET /containers/{id}/changes` — одна команда. **Складність: низька.**

### 1.4 Керування реєстрами
**У кого:** Portainer, Docker Desktop, JetBrains.
Логін у приватні registry, збережені креденшели, пошук і pull образів прямо з Docker Hub / GHCR, push власних образів.

**У нас:** pull працює лише для публічних образів, push немає взагалі.
**Складність: середня** (Engine API це вміє, потрібен UI + зберігання секретів у keychain).

### 1.5 Зміна ресурсних лімітів на льоту
**У кого:** Portainer, Docker Desktop.
CPU/RAM ліміти контейнера можна змінити без пересоздання — `POST /containers/{id}/update`.

**У нас:** ліміти видно лише в Inspect, змінити не можна.
**Складність: низька.** Логічне продовження вже зробленого редагування env — тільки тут навіть перестворення не потрібне.

## 2. Автоматизація і командна робота

### 2.1 GitOps: стеки з Git-репозиторію + вебхуки
**У кого:** Portainer (ключова фіча), Dokploy, Komodo.
Стек тягнеться з гілки репозиторію й передеплоюється автоматично — за розкладом або по вебхуку з CI. Джерело правди — репозиторій, а не редактор у вебі.

**Оцінка для вас:** саме це закриває сценарій «задеплоїти без ssh на сервер». Але це вже інша категорія продукту (CD-система), і в десктопному однокористувацькому інструменті цінність нижча, ніж у Portainer.
**Складність: висока.**

### 2.2 Шаблони застосунків (app templates)
**У кого:** Portainer, Docker Desktop (Docker Init).
Каталог готових стеків: postgres, redis, n8n, monitoring — розгортаються з форми за 3 кліки.

**Для нас:** корисно як «мої шаблони» — зберегти власний compose-стек і розгортати його на будь-якому з 5 серверів. **Складність: середня.**

### 2.3 Аудит дій і RBAC
**У кого:** Portainer BE.
Хто що зробив, коли; ролі та команди.
**Для однокористувацької десктопної апки RBAC не потрібен**, але **локальний журнал власних дій** (що я запускав/видаляв на якому сервері) — дешево й рятує, коли «хто зупинив прод о 3 ночі».
**Складність: низька.**

### 2.4 Заплановані задачі
**У кого:** Portainer (edge jobs), Komodo.
Періодичний prune, рестарт о 4:00, бекап тому за розкладом.
**Складність: середня** (у нас уже є вся інфраструктура виконання команд).

## 4. Що я б робив у наступну ітерацію

Порядок — за співвідношенням «користь ÷ зусилля» саме для вашого сценарію (5 серверів, ~80 контейнерів, Python/Docker-стек):

1. **Шари образу + diff контейнера** — дві команди Engine API, півдня роботи, закривають найчастіше «чому образ такий великий» і «що змінилось усередині».
2. **Ліміти CPU/RAM на льоту** — одна команда API, форма на 4 поля.
3. **Сканування вразливостей через Trivy-контейнер** — без ліцензій і хмари, дає те, за що Docker Desktop бере гроші.
4. **Приватні реєстри + push** — без цього цикл «зібрав → відправив» не замикається в апці.
5. **Журнал власних дій** — дешево, і на проді з read-only режимом це логічне доповнення.
6. **Сповіщення в Telegram** — алерти вже є, лишилось вивести їх назовні; для 5 серверів це різниця між «я дізнався зранку» і «я дізнався одразу».

**Свідомо НЕ робив би:** Kubernetes/Swarm, RBAC, GitOps-платформу, автоматичні домени. Це або інша категорія продукту, або вимагає інфраструктури, яка вбʼє головну перевагу — 11 МБ і 30 МБ RAM.

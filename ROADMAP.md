### Слабкі місця того, що вже є

1. **Логи бачать лише буфер.** Пошук працює по 8 000 останніх рядків у пам'яті. Якщо помилка була вчора — її не знайти, треба йти в термінал і `grep` вручну.
2. **Немає агрегованих логів стека.** Щоб зрозуміти ланцюжок «web → celery → postgres», треба клікати між контейнерами й зіставляти час очима.
3. **Стек без `working_dir` (створений не через `compose up`) не має compose-дій** — кнопки просто вимкнені, без пояснення, де взяти шлях.
4. **Термінал хоста не переживає ресайз вікна** — розмір задається при відкритті (обмеження системного `ssh` без PTY-контролю).
5. **Секрети.** Працює лише ssh-agent / ключ без пароля. Паролі та passphrase не підтримуються, keychain не задіяно.
6. **Один термінал на об'єкт.** Не можна тримати два shell-и в одному контейнері поруч.
7. **Немає зворотного зв'язку про масштаб.** 81 контейнер — а фільтр лише текстовий: немає «тільки запущені», «тільки з помилками».

## 3. Рекомендація: наступні 5

Якщо робити одну ітерацію, я б узяв саме ці — вони закривають найчастіші сценарії й не конфліктують між собою:

1. **A1 — пошук по всій історії логів** (найбільший розрив між очікуванням і реальністю)
2. **A3 — швидкі фільтри контейнерів** (дешево, а біль від 81 рядка щоденний)
3. **A5 + A6 — port-forward і «відкрити в браузері»** (унікальна перевага над Docker Desktop, там цього немає)
4. **B1 — `docker system df` з prune** (диск на сервері — регулярна проблема)
5. **C8 — read-only режим для прод-профілів** (дешево, знімає ризик випадкової дії на проді)

**Свідомо відкладаю:** створення контейнерів через форму (B7) і build (B8) — на практиці це майже завжди робиться через compose-файл, який уже можна редагувати; дашборд усіх серверів (C5) — красиво, але допомагає рідше, ніж здається.

## 4. Технічний борг

- `host_stats` / `host_ps` більше не використовуються (замінені на стрім `host_monitor`) — прибрати
- Файлові операції контейнера (`fs_*`) досі йдуть через `docker exec` + archive API; хостові вже через постійний агент — уніфікувати підхід
- Немає жодного автотесту; мінімум — unit на `parse_ls` і на парсер блоків монітора
- `ui/js/app.js` — 1 259 рядків одним файлом; варто розбити на модулі перед наступною великою фічею
- Немає обробки «сервер недоступний» у половині хост-команд — тости показують сирий текст помилки
